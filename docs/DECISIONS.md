# Decisions

- NestJS 11, Mongoose 8, Node 26.
- No Docker for development or tests; tests use mongodb-memory-server (MongoMemoryReplSet). docker-compose.yml is provided for optional use only.
- Permissions (@lc/shared, one per PRD §3 row; S cells allowed at role level): leads.create, students.create, enrollments.updateCourse, courses.manage, rooms.manage, placement.schedule, placement.grade, classes.manage, enrollments.assign, enrollments.confirm, students.search, students.viewProfile, students.update, sessions.manage, sessions.view, attendance.take, attendance.viewHistory, grades.enter, grades.view, fees.update, discounts.decide, fees.view, reports.view, users.manage (ADMIN+MANAGER), settings.update (MANAGER only; not in PRD matrix).
- Shared zod contracts (packages/shared/src/schemas): DTO ids are 24-hex strings; instants are ISO-8601 strings; date-only fields (dob, heldOn, dueDate, startDate/endDate, report from/to) are `YYYY-MM-DD` in both inputs and responses. Weekday is ISO 1=Mon..7=Sun. Reasons are shape-only (`zReason`, may be empty) so services raise REASON_REQUIRED; score, weight, discount, session-range (92 days) rules stay in services. PATCH bodies are `.partial().strict()`; immutable fields (course/room/class `code`, class `currentSize`, user `email`/`role`) are excluded so they yield VALIDATION_FAILED.
- Shape inventions: `PUT /placement-tests/:id/results` body is the bare array; `PUT /assessments/:id/grades` `confirm` defaults false; `GET /attendance/summary` requires `groupBy`; `POST /users` returns `{ user, tempPassword }`; `POST /users/:id/reset-password` returns `{ tempPassword }`; `POST /classes/:id/sessions/cancel-future` returns `{ cancelled }`; `POST /sessions/check-conflicts` returns `{ conflicts: SessionConflictDto[] }`; report DTOs use `{ totals, rows }` (attendance: byClass/byStudent/overThreshold; academic: rows/distribution/passRate/failRate); rates are 0..1 fractions; `GET /reports/:type/export` query = union of filters + `format`; `RoomStatus` (ACTIVE|INACTIVE) lives in schemas/rooms.ts; boolean query params use `zBoolQuery` ('true'|'false'|'1'|'0').
- Auth: change-password revokes all refresh tokens and rotates the cookie but already-issued access tokens stay valid for up to 15 minutes (stateless JWT). `JWT_REFRESH_SECRET` is optional in the env schema and reserved/unused: refresh tokens are opaque random values stored as sha256. The web client must dedupe concurrent `/auth/refresh` calls (single in-flight promise), because rotation is single-use and a reuse outside the grace window (below) revokes every session of the user.
- Enrollment uniqueness: unique partial index `uniq_active_student_course` on enrollments `{studentId, courseId}` with `partialFilterExpression: { status: { $in: [PENDING_PLACEMENT, WAITING_CLASS, ENROLLED] } }` (supported by the Mongo version used in tests; `ACTIVE_ENROLLMENT_STATUSES` in `database/active-enrollment.ts`). `createPending` does a pre-check for a clean error and maps E11000 from the index to `ENROLLMENT_EXISTS`, so concurrent calls cannot both succeed (covered by a 3-way concurrent test). Note this index also constrains later transitions into an active state (e.g. un-cancelling) when another active enrollment exists.
- Events: `@nestjs/event-emitter@^3` (v12 is ESM-only and incompatible with Nest 11/Jest CJS); `EventEmitterModule.forRoot()` lives in AppModule. Notifications API read-side is `NotificationsApiService` in modules/notifications (the write-side `NotificationsService.notify` stays in CommonModule).
- Date-only storage: date-only fields (dob, startDate/endDate, dueDate, heldOn, …) are stored as a `Date` at VN midnight of that day (`fromDateOnly(day)` = `startOfVnDay`) and serialized with `toDateOnly(d)` (= `vnDay`) from `@lc/shared`. Never use `toISOString().slice(0, 10)`: VN midnight is 17:00Z of the previous day, so it returns the wrong date.
- Roles: `RolesGuard` reads `@Roles` with `getAllAndOverride`, so a handler-level `@Roles` replaces the class-level one (it does not intersect or merge) — repeat the roles on the handler if you need a subset.
- Time: Mongoose `createdAt`/`updatedAt` come from ClockService too — every schema uses `timestamps: clockTimestamps` (`database/schemas/helpers.ts`), backed by `clockHolder` which `ClockHolderBinder` binds to the app's ClockService (FakeClock in tests). New schemas must use it (an e2e test checks every registered model).
- Refresh reuse grace: presenting a refresh token rotated < 10 s ago (or losing the atomic claim to a concurrent rotation) returns 401 UNAUTHENTICATED without revoking other tokens; later reuse still revokes every token of the user. The web client serialises refreshes across tabs with `navigator.locks` (`lc-refresh`) and shares new tokens over `BroadcastChannel('lc-auth')`.
- Usernames are canonical: STUDENT usernames (student codes) uppercase, email usernames lowercase (User pre-validate hook); login normalises input the same way (contains `@` → lowercase, else uppercase).
- Errors: Mongoose `ValidationError` → 400 VALIDATION_FAILED with `details.fields` (path → message); `CastError` (malformed ObjectId) → 404 NOT_FOUND.
- Cross-lane DI contracts live in Lead-owned `apps/api/src/common/contracts/`: `INVOICE_CREATOR`, `OUTSTANDING_CHECKER` (L-FEES implements), `SCHEDULE_CONFLICT_CHECKER` (L-SCHEDULE implements). The global `ContractsModule` provides no-ops; the implementing lane provides + exports the token from its own module, and the Lead adds that module to each consumer's `imports` at merge (explicit imports win over the global no-op). Consumers inject by token only.
- `@lc/shared` resolves from `packages/shared/src` in dev, typecheck, lint and tests (tsconfig `paths`, jest `moduleNameMapper`, vite alias); the API production build (`tsconfig.build.json`) resolves the built `dist`, which is produced by the package's `prepare` script on install, by `pnpm --filter api build`, and by the merge gate.
- Test factories generate codes outside every service namespace (HV1999…, HD199901…, PT199901…, `F-` class/course/room codes) so they never collide with CounterService codes.
- Notification `refType` is the closed `NotificationRefType` enum in `@lc/shared` (CLASS, SESSION, STUDENT, INVOICE, ASSESSMENT, ENROLLMENT, PLACEMENT_TEST, PAYMENT).

## Lock-key protocol (schedule/class invariants)

Snapshot-isolated transactions cannot see each other's inserts, so invariants that span documents (no room/teacher overlap, sessions inside the class window, no sessions on a deleted class) are serialised through counter documents:

- Keys: `lock:class:<classId>`, `lock:room:<roomId>`, `lock:teacher:<teacherId>`, bumped with `CounterService.next(key, s)` **inside the writing transaction and BEFORE reading the invariant**. Two writers on the same key write-conflict; the loser is retried by `withTransaction` and then sees the winner's data.
- Who bumps what:
  - Session create / update / bulk create (`ScheduleService.lockSchedule`): class, then room, then teacher — always in that order.
  - Class delete and class date change (`startDate`/`endDate` differs from the stored value; then 422 `SESSION_OUTSIDE_CLASS_RANGE` with `details.sessionIds` when a SCHEDULED session would fall outside the new VN-day window): class.
- Wave 2 must follow it: placement tests bump room + teacher (same order as sessions) before their conflict check; enrollment assign/transfer bump `lock:class:<id>` of every class whose seats or roster they read (ascending id order when more than one).
- Inside a transaction never run operations concurrently on the same `ClientSession` (`Promise.all` with `s`): issue them one by one; keep `Promise.all` only for session-less reads.

- Classes: sessions can only be created/moved for PLANNED|ONGOING classes (422 `CLASS_NOT_OPEN` otherwise, also for the bulk dry-run). `GET /classes?open=true` lists exactly those (full or not; `hasSeat` additionally needs a free seat); the session form class picker uses it, room pickers use `status=ACTIVE`, and a class `defaultRoomId` must be an ACTIVE room when set or changed.
- Student writes (`PATCH /students/:id`, `/students/me/contact`, document upload/remove) commit together with their audit row; a `fullName` change also renames the STUDENT user in the same transaction. Uploaded files are deleted when the transaction fails; removed files are unlinked only after commit.
- Shared API helpers: `escapeRegex` (`common/util/escape-regex.ts`) and `isDuplicateKey` / `DUPLICATE_KEY` (`common/util/is-duplicate-key.ts`); do not re-declare them in modules.

## Wave 2 decisions

- **D11 InvoiceCreator returns the id:** `createForEnrollment(enrollmentId, s): Promise<Types.ObjectId | null>` returns the existing or new TUITION invoice id (no-op returns `null`). L-ENROLL writes `enrollment.invoiceId` from it (fees never writes enrollments). An enrollment chain's invoice is found by `enrollment.invoiceId`, else `invoices{enrollmentId, kind: TUITION}`, else by walking back `transferredFromId`. Transfer does NOT call InvoiceCreator: the new enrollment copies the old `invoiceId`; `invoice.classId` stays the original class.
- **D12 FEES_OUTSTANDING = 403** (PRD FR-GRD-07 wins over the W0 422 in `errors.ts`; fixed in Task 0).
- **D13 Attendance roster is point-in-time:** a student is on session `s`'s roster when an enrollment `e` with `e.classId = s.classId` has `s.startAt` inside an ENROLLED span: from the `at` of a history entry `to: ENROLLED` to the `at` of the next entry `from: ENROLLED` to TRANSFERRED|RESERVED|CANCELLED (open if none; COMPLETED does not close a span). Pure `enrolledAt(history, instant): boolean` in `modules/attendance/roster.ts`.
- **D14 Gradebook roster:** students required to have a score on `confirm:true` = class enrollments with status ENROLLED|COMPLETED at write time. Scores of students who left are kept and still returned by `GET /assessments/:id/grades` with `left: true`, not required.
- **D15 Placement results:** `PUT /placement-tests/:id/results` overwrites per candidate (idempotent). Score AND level non-null moves the enrollment PENDING_PLACEMENT -> WAITING_CLASS (`placementLevel`, `waitingSince = now`, history); already WAITING_CLASS from this test only updates `placementLevel`; any other enrollment status fails the whole request 422 `ENROLLMENT_INVALID_STATE` with `details.enrollmentIds`. All candidates graded -> test COMPLETED. An enrollment cannot be a candidate of two SCHEDULED tests (422 `ENROLLMENT_INVALID_STATE`); re-adding an existing candidate is skipped.
- **D16 Windows and locks:** a teacher may edit attendance while `now < session.endAt + settings.teacherAttendanceEditDays x 24h`; staff unlimited; MANAGER cannot write attendance (PUT/PATCH = T, S). Gradebook `lockedAt = startOfVnDay(addVnDays(heldOn, gradeLockDays))`; `isLocked = now >= lockedAt && !(unlockedUntil > now)`; a lock blocks every grade write (draft PUT, confirm PUT, PATCH).
- **D17 Absence warnings:** after each attendance PUT/PATCH commits, for each student of the session compute `absenceRate` over all their records in that class; `> threshold` with no `attendance_warnings{studentId,classId}` -> insert (unique index guards races) + `notify([student user, all ACTIVE ACADEMIC_STAFF], ATTENDANCE_WARNING, refType STUDENT)`; `<= threshold` with a warning -> delete. `AttendanceStatsService.warningFlags(classId): Promise<Map<string, { absenceRate: number; warning: boolean }>>` (key = studentId string) is exported from `AttendanceModule`.
- **D18 Contract tests in lanes:** a lane consuming a token tests only with fakes via `createTestApp({ overrides: [{ provide: INVOICE_CREATOR | OUTSTANDING_CHECKER, useValue }] })`; real invoice data is checked in Task M (flow test). L-FEES tests the real implementation via `t.app.get(INVOICE_CREATOR)` once FeesModule provides it.
- **D19 Confirm-class banner (E-06):** `ConfirmClassBanner` exported from `features/enrollments`, shown on `/me/classes`; Task M mounts it on the student home (`features/home/pages/student-home.tsx`, Lead at merge).
- **D20 `/fees` footer total** = sum of the rows of the current page (no extra endpoint).
- **D21 Wave 2 notifications:** assign/transfer -> `CLASS_ASSIGNED` to the student's user (refType CLASS, refId class); grades confirm -> `GRADES_PUBLISHED` to the roster students (refType ASSESSMENT); discount decision -> `DISCOUNT_DECIDED` to the proposer (refType INVOICE); payment -> `PAYMENT_RECORDED` to the student's user (refType INVOICE). Sent AFTER commit; notify failures are only logged.
- **R22 Durable class history (history scope):** `enrollment.classHistory: ObjectId[]` holds every class the enrollment was ever seated in; assign `$addToSet`s the class and transfer creates the new enrollment with `classHistory: [toClass]`, both inside their existing txns; the stint-opening history entry (`to: ENROLLED`) carries `classId`. A student's **history scope** (`ScopeService.studentClassIds(_, 'history')`) = union of `classId` and `classHistory` over all their enrollments, so RESERVED -> resume (`classId = null`) -> reassign keeps the old class's attendance, results, assessments and transcript visible. Results/transcript lookups match `{ studentId, $or: [{ classId: X }, { classHistory: X }] }`. The D13 roster also queries `classHistory`; a stint counts for class X only when its opening entry's `classId` is X (legacy entries without `classId` count only when `enrollment.classId` is X).
- **R23 Late-assignment due date:** TUITION `dueDate = addVnDays(max(toDateOnly(class.startDate), vnDay(now)), settings.invoiceDueDaysAfterStart)` — a student assigned after the class started is due N days from the assignment day, never in the past.

## Wave 3 decisions

- **D22 Student profile summary (FR-STU-02, replaces D7):** `summary.averageScore` = mean (rounded to 2) of the student's non-null `ResultDto.average` over every class in `studentClassIds('history')`, null if none; `summary.outstandingBalance` = sum of `balance` over the student's invoices with status != VOID. Computed in admissions by reading the models directly, using `weightedAverage` and confirmed assessments only.
- **D23 Student email login (FR-ADM-04, closes D8):** STUDENT only. When the login input contains `@` and matches no `users.username`, look up `students` by lowercase `email`, `deletedAt: null`, with a `userId`; exactly **one** match logs into that user with the user's password; zero or >= 2 matches -> `401 INVALID_CREDENTIALS` (never reveals the duplicate). Staff still log in with their email username as before.
- **D24 Current classes (R26):** `StudentDto.currentClasses: { classId, code }[]` (ENROLLED only, sorted by code); a teacher sees only classes within `teacherClassIds`. The `/students` "Lớp hiện tại" column joins the codes with ", ". Task 0 adds the field to `StudentDto` / `StudentBriefDto` and the admissions mapper fills `[]` until L-01 provides the data.
- **D25 Dashboard (FR-RPT-06):** `activeStudents` = distinct students with an ENROLLED enrollment; `ongoingClasses` = classes `PLANNED|ONGOING`; `sessionsToday` = SCHEDULED sessions with `startAt` inside today (VN); `overdueInvoices` = invoices matching `overdueFilter(now)`; `waitingEnrollments` = enrollments WAITING_CLASS. Adds `todaySessions` and `admissionsTrend` (last 6 months, oldest first).
- **D26 Report definitions:**
  - Admissions (FR-RPT-01): `leads` = leads with `createdAt` in [from,to] (VN days); `newProfiles` = students with `createdAt` in range; `conversionRate` = (leads in range with status PROFILE_CREATED) / `leads`, 0 when `leads` = 0; `enrolled` = enrollments with a history entry `to: ENROLLED` whose `at` is in range; `waiting` = current WAITING_CLASS count (snapshot). By course: lead `interestedCourseId`, student/enrollment `courseId`.
  - Attendance (FR-RPT-02): attendance records of sessions with `startAt` in range; rates via the shared helper, rounded to 4; `overThreshold` = student-class pairs with `absenceRate > attendanceWarningThreshold` over the records in range.
  - Academic (FR-RPT-03): confirmed assessments with `heldOn` in range only; a student-class average = `weightedAverage`; class average = mean of student averages (rounded to 2); `distribution` by `classify` per student-class; `passRate`/`failRate` over student-classes that have an average.
  - Finance (FR-RPT-04): `revenue` = sum of VALID payments with `paidAt` in range; invoice metrics over non-VOID invoices with `createdAt` in range: `totalDue` = sum finalAmount, `outstanding` = sum balance, `overdue` = sum balance matching `overdueFilter(now)`, `totalDiscount` = sum of APPROVED discount.amount; `groupBy=month` by VN month (`paidAt` for revenue, `createdAt` for invoices), `course`/`class` by invoice.courseId/classId (payments via their invoice).
    Because the invoice metrics only count invoices *created* in range, the finance report's "Quá hạn" (overdue) differs from the dashboard's overdue count (D25, every invoice matching `overdueFilter(now)` regardless of creation date). This is by design, not a mismatch.
  - Addendum (W3 Ruling R2, grouping details D26 left open): admissions `newProfiles` by course uses the student's lead `interestedCourseId`, falling back to the courseId of the student's earliest enrollment; students with neither count only in the totals. Admissions rows are the courses with any non-zero metric (plus the filtered course). Finance rows whose invoice has a null course/class (`groupBy=course|class`) use key `'none'`, label "Khác"; `groupBy=month` rows are labelled "Tháng MM/YYYY". Revenue is grouped by the payment's invoice. A class transfer creates a new enrollment (`modules/enrollments/assignment.service.ts` transfer: the old row becomes TRANSFERRED, a new ENROLLED row with its own history is created), so "Đã ghi danh" (`enrolled`) includes transfers.
- **D27 Portal data access:** `features/home` uses hooks/queries exported by the owning feature when they exist; otherwise it calls GET endpoints from `features/home/api.ts`, never editing another feature. UI changes in another feature (P-02) go through a contract request; the Lead does them in Task M.
- **D28 Seed:** the new `seed:demo` runs through the real services (`NestFactory.createApplicationContext(AppModule)`: convert lead, placement, assign, bulk sessions, attendance, grades, invoices/payments) so `classHistory`, history stamps and InvoiceCreator invoices exist; demo accounts stay in the README. `seed:large` (NFR-02) bulk-inserts raw documents **with** every W2 field (classHistory, stamps); sizes come from env.
- **GET /assessments/pending (W3 Task 0):** TEACHER only; assessments of `teacherClassIds` (main or assistant) with `confirmedAt: null`, `heldOn` <= today (VN) and `!isLocked`, sorted by `heldOn` ascending; each row is `AssessmentDto` + `classCode` + `className`. The static route is declared before any `assessments/:id` route.
